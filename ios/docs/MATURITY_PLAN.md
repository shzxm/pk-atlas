# 药时成熟化质量门禁与路线图

> 这里只陈述已实现、未完成的验证与后续可以开发的能力。药代模型是群体数学估算，不能把模型输出直接当作处方或自动服药建议。

## 产品原则

1. **事实与推测必须明确分层。** 真实服用、用餐、Apple 健康读取、已采用数学计划、A/B 假设、血药浓度模拟，使用不同标签与记录来源，不互相冒充。
2. **本地优先、云端透明。** 可以脱机查看已经缓存的资料，联网后按既定“最后成功上传设备优先”策略同步。该策略存在不同设备离线修改互相覆盖的风险；不能把“最后成功上传”宣传为“永不丢数据”。
3. **每个功能必须具有回归验收。** 数据纯函数单元测试、原生页面测试、iPhone 模拟器手势测试、发布包内资源验证、签名版本检查。
4. **隐私默认最小化。** 操作日志和脱敏诊断不含药物名称/剂量/账号/服务器地址/设备指纹；完整记录导出只能由用户主动触发。
5. **数学和临床解释分离。** 任何“模型时间节点”都不是建议摄入时间，参考线不是个人实测值。

## 尚未完成的 P0 真正成熟度门槛

- **HealthKit 真机完整验收**：使用带有 HealthKit entitlement 的实际签名 IPA，检查首次授权、授权后静默查询、系统分析中 PKAtlas `.ips` 崩溃记录；模拟器通过不代表真机稳定。
- **APNs 真实推送验收**：提供合法的推送签名与服务器 Apple 凭证；测前台、后台、退出 App 与网页修改通知的最终一致性，iOS 仍可能延迟后台唤醒。
- **多设备一致性故障注入**：两台设备 A/B 离线交叉修改、上传请求超时后重复、最后提交顺序、数据库恢复等端到端测试。明确“最后上传覆盖”可能带来的损失，并完善可恢复快照。
- **隐私和开源清查**：在推到任何公开仓库前用脚本核查 URL、域名、IP、私密配置、plist、构建包、测试快照和 Git 历史，严禁将服务器私钥/账号数据提交到公开 GitHub。
- **签名发布可靠性**：临时 GitHub 浏览器仅支持 ZIP（ZIP 内含未经改动的 IPA）；要实现 GitHub CLI 真正自动化发布，所有者须进行一次性 OAuth 授权。Apple App Store 对下载可执行 JS 的规定另行审核，不能直接视为可上架。

## 下一批有差异化价值的亮点（尚未开发）

1. **时间旅行 / 事件解释器**：选择过去任何时刻，在同屏展示当时真实记录、采用计划、饮食匹配、模型版本和产生该条结果的原因；定位“这条蓝色虚线是从哪几个节点算出来的”，但不生成服药建议。
2. **模型不确定性视图**：将群体参数的文献范围标为上下包络带，并明确识别“有研究范围”和“根本没有可靠范围”的区别。避免虚构个体血药浓度置信区间。
3. **观测日志与相关性探索**：允许用户主动记录睡眠、感受、症状和副作用，展示时间重合而不推断因果；可选接入授权的健康数据。
4. **药物与证据溯源卡片**：每个参数展示原文献、制剂类型、研究人群、是否空腹、当前模型版本和最近变更，方便辨别“数学模型准确”与“现实情况不适用”。
5. **本地数据时光保险箱**：保留若干个加密历史快照和一键预览差异，误操作或多设备最后上传覆盖之后仍有明确的本地恢复入口。
6. **长期压力测试与无障碍**：10,000 条记录、300 条饮食、600 采样点、低电量/弱网、切换时区、VoiceOver、动态字号、Reduce Motion、iPad 多窗口、iPhone Duo 适配。

## 每轮验收流程

独立实现功能 → Swift 编译 → 该功能纯逻辑 XCTest → 真实模拟器 UI 测试 → 已完成功能的回归 → 完整自动测试 → unsigned IPA/ZIP 的 SHA-256 和内部版本核对 → 私有 GitHub Release → 同步更新服务端签名版本清单 → 列出仍需真实设备测试的部分。
