为什么这里不直接覆盖云端？

服药、饮食和已采用的模型可能被另一台设备修改。中心只读比对；需要合并时使用主页带版本检查的自动同步，避免错把较旧的本机数据写到云端。

导出与迁移

下载文件可能包含完整服药历史、个人参数和模型方案。请保存在私人设备，不要上传至公开网盘。

“原导入格式”采用当初 import_ios_journal.py 接受的 exportSource/experiences/ingestions JSON 结构，可交给该脚本重新导入；“本站归档”额外保留 journal 完整元数据与网站修改信息。由于原始文件已不可见，体验的原始分组及未导入的原 App 字段不能重建。

从 JSON 文件安全合并

只读取并预览；不会立即修改数据。

兼容格式与合并原则

支持新版完整备份、旧版药时五分区 JSON、早期“导出本机草稿”文件、本站 iOS Journal 17.1 标准化归档 JSON 和原导入格式 exportSource: iOS Journal 17.1 的文件。按记录 ID 去重；遇到同一 ID 但内容不同、方案冲突或云端版本发生变化，会停止写入，不会静默覆盖。

仅在云端账号完全没有服药、饮食、周期或方案时，自动恢复导入文件中的个人设置和已采用反算方案。已有账号默认保留现有设置。
